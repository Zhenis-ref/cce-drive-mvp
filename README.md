# \# CCE-Drive-MVP

# A research simulation benchmark for testing \*\*Candidate Compression Evaluation (CCE)\*\* in autonomous vehicle motion planning.

# \## Project idea

# In many motion-planning problems, evaluating every action deeply provides a strong quality reference, but quickly becomes computationally expensive. The goal of this project is to test whether we can \*\*reduce the number of deep action evaluations\*\* without degrading safety relative to a brute-force baseline.

# This benchmark compares two planners:

# \* \*\*Brute-force planner (BF)\*\* — deep evaluation over the full action lattice.

# \* \*\*CCE planner\*\* — a two-stage planner:

# &#x20; \* a fast coarse preview over all actions;

# &#x20; \* selection of a reduced candidate subset for deep roll-out.

# The project uses a structural compression logic inspired by external pressure and internal trajectory divergence in the spirit of a ΔN–ΔD-style interpretation, rather than a simple top-k filter after a coarse heuristic.

# \## What is being tested

# Core hypothesis:

# > CCE can preserve safety at the level of brute-force, or close to it, while reducing the number of expensive deep action evaluations.

# Main metrics:

# \* \*\*BF safety\*\* — fraction of safe outcomes for brute-force.

# \* \*\*CCE safety\*\* — fraction of safe outcomes for CCE.

# \* \*\*Matched safety\*\* — fraction of runs where CCE is not worse than brute-force in safety outcome.

# \* \*\*Compression Ratio (CR)\*\* — ratio of BF deep evaluations to CCE deep evaluations.

# \* \*\*Latency\*\* — planning time.

# \## Scenarios

# The current version includes four baseline stress scenarios:

# \* `hard\_brake` — sudden braking of the leading vehicle;

# \* `obstacle` — sudden obstacle on the path;

# \* `cutin` — cut-in / lane intrusion by another vehicle;

# \* `ice\_trap` — low-friction regime with degraded controllability.

# \## Final results

# Results below were obtained with 30 seeds per scenario.

# 

# | Scenario   | BF safety | CCE safety | Matched safety | Mean CR |

# | ---------- | --------: | ---------: | -------------: | ------: |

# | hard\_brake |     0.900 |      0.900 |          1.000 |  4.777x |

# | obstacle   |     0.700 |      0.700 |          1.000 |  4.905x |

# | cutin      |     1.000 |      1.000 |          1.000 |  4.654x |

# | ice\_trap   |     0.233 |      0.200 |          0.967 |  5.272x |

# 

# \### Short conclusion

# \* In \*\*3 out of 4 scenarios\*\*, CCE reaches the same safety level as the brute-force baseline.

# \* At the same time, the mean compression ratio remains around \*\*5x\*\*.

# \* The hardest regime is `ice\_trap`, where the baseline itself performs poorly. In that regime, CCE remains close to BF, but not identical.

# \## Why this matters

# This repository shows that \*\*structural compression of the action space\*\* can be transferred to safety-critical motion planning.

# In this benchmark, CCE acts not as a decorative heuristic, but as a research mechanism for:

# \* reducing combinatorial burden;

# \* preserving decision quality;

# \* balancing safety and computational cost.

# \## Limitations

# This is \*\*not a production autopilot\*\* and not a real-vehicle deployment stack.

# The current benchmark is a research MVP with clear limitations:

# \* two-dimensional simulation;

# \* simplified vehicle physics;

# \* discrete action lattice;

# \* short planning horizon;

# \* no perception stack, maps, or real sensors.

# Therefore, results should be interpreted as a \*\*proof of principle in a laboratory benchmark\*\*, not as a final driving system.
